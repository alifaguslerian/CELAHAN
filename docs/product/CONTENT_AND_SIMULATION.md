## Conceptual process

The retained eight educational stages are pre-engagement, information gathering, scanning, manual testing, risk assessment, reporting, retesting and closure. The page explicitly says that the website performs none of these operations. Closure of represented assessment material is separate from actual portal-record retention.

These stages describe an academic model, not service packages, assessed targets, scan logs, completion percentages or a replacement report dataset. User assertions about incidents are not diagnoses.

## Future report content

Any replacement public example needs explicit review before publication. DEC-69 authorizes one fictional order-portal example for the private draft editor. Private reports use versioned immutable publication, exact project ownership checks and draft/internal-note separation. An entered website must never produce findings or become a resource URL.

User programmer-change assertions and illustrative admin review events are distinct. Corrections to an actually published future version create a new version with a change note rather than silently changing history. No generated PDF, uploads, public share token or real assessment is implied.

## Consultation and messages

W4 intake stores authenticated requests in private tickets. The server validates the requested fields and the optional W5C package code. Proposed schedules become appointments after admin confirmation. Failed writes must not claim success. Private drafts stay in memory.

DEC-71 prices are illustrative per project. Package selection carries a public catalog code into intake and does not create a charge. The DEC-69 and DEC-70 support rules remain separate.

## Privacy and metadata

Disclose actual account storage, necessary cookies, local email capture and the isolated database. Public enrollment/delivery, retention/deletion/backups, processors/regions and privacy contact remain release gates. Synthetic project examples do not make real account identities nonpersonal.

Use localized generic public metadata. Account/private/admin pages remain noindex and must independently authorize all data. No report data, contact details, entered website, message or token in URL parameters, logs, public assets, analytics, external AI or social previews. No fabricated clients, research, testimonials, certifications or guarantees.
