## Authorization and environment

The owner authorized W2 on October 31, approved allowlisted synthetic enrollment, mandatory email verification, local-capture recovery and controlled TOTP-protected admin provisioning, and delegated the database choice. The implementation uses one dedicated Neon Free PostgreSQL 17 project in Singapore. No managed Neon Auth, paid add-on, production identities, public enrollment, external email, domain/DNS changes, deployment or later package is included. Git was not used and `.git` was not inspected.

Node 26.10.0, npm 12.0.2, Next.js 16.4.3, React/React DOM 19.3.1, TypeScript 5.9.3 and Python 3.12 were retained. Added exact dependencies: Better Auth 1.7.14, pg 8.23.1, server-only 0.0.1 and development-only @types/pg 8.23.1. Reasons are recorded in [README](../../README.md#dependency-and-asset-choices). No ORM or auth CLI package was added. `npm ls --depth=0` completed without invalid dependencies; Python `pip check` reported no broken requirements.

The Neon account plan was verified as Free before setup. A first creation request specifying a suspend interval was refused with HTTP 412; the successful retry retained provider defaults and a fixed 0.25-CU compute. No paid feature was enabled. The source [pricing page](https://neon.com/pricing) listed 100 CU-hours and 1 GB per project on Free when checked; this is a dated limit, not an unlimited-use guarantee. Provider history remains its default six-hour window, not a tested backup/restore procedure.

## Schema and secret boundaries

- Generated and reviewed `database/001-identity.sql` from the installed Better Auth configuration, then applied it together with `002-project-access.sql` to the empty isolated database. These contain identity/session/verification/TOTP/rate-limit tables, minimum ownership association and metadata-only privileged audit. They do not implement tickets, reports or support.
- `npm run db:migrate` reapplied successfully without changing already-applied migrations. The runner checks saved hashes and uses a transaction/advisory lock. Migration corruption, simultaneous migration and database-outage rollback were not fault-injected.
- Prepared a runtime role with DML on auth tables and SELECT on ownership association. Real database assertions verified no schema CREATE or project-assignment INSERT privilege. The app uses a pooled URL; migration/admin scripts use a direct owner URL. Both require verified Neon TLS.
- Runtime secrets live only in ignored `.env.local`; owner credentials live in separate ignored `.env.database.local`, which Next.js does not load. No working values appear in the template, source, saved SQL or browser bundles. Configuration rejects non-loopback app/mailbox origins, real email domains, unknown identities, an unexpected database name and unverified database TLS.
- Public configuration remains disabled by default. The local mailbox is a bearer-protected loopback service with at most 100 in-memory records. Codes expire after five minutes; expired entries are purged on the next mailbox request and all entries disappear on process exit. No code, password or recovery link is logged.

### Real database/session coverage

The integration suite creates only configured synthetic accounts with random passwords in memory and refuses cleanup if the database name or identities are unexpected. It verifies signup persistence, verification-before-login, hashed OTP storage and replay denial, generic failures, unknown/privileged-field rejection, foreign/missing Origin denial, owned profile changes and escaped text, two-user session/resource isolation, identical foreign/nonexistent resource denial, current project-derived header capabilities and ownership revocation.

It also verifies logout against a copied old session, database-session expiry, password reset revoking sessions and the old password, reset-code replay rejection, refusal to grant admin before TOTP enrollment, mandatory second factor after role grant, no admin access during a password-only challenge, trusted admin navigation, single-use backup recovery codes, revoked admin/disabled account denial, database-backed login rate limiting, metadata audit and nonplaintext password storage. Runtime privilege checks use the actual restricted credential.

Header visibility is not counted as authorization evidence by itself. Owned-resource and admin endpoints are tested directly. The minimal project resource returns only an authorized ID; full project/report semantics remain W5 work. Private API and personalized HTML cache headers were checked for no-store behavior.

## Dependency review and remaining limits

`npm audit --omit=dev --json` reported zero known runtime advisories. The full audit reported 12 moderate findings propagated through the existing ESLint/minimatch development dependency chain. The root advisory is [GHSA-g3hv-75wg-m249](https://github.com/advisories/GHSA-g3hv-75wg-m249), patched in minimatch 11.0.1. No major override, forced downgrade or disabled rule was used to conceal it. The application does not accept user glob patterns; dependency maintenance remains outstanding and no full audit pass is claimed.

Not established: public enrollment/email deliverability; HTTPS/Secure-cookie/hosting behavior; operational admin recovery; retention/deletion/backup restoration; full CSP; complete ticket/report/admin workflows; full cross-account CDN/RSC/cache permutations; server-wide network interception; Firefox/WebKit W2 passes; physical phones/native zoom/screen reader/full WCAG; Lighthouse, LCP/CLS/INP or production load behavior. Earlier W1 browser-engine limitations remain historical evidence, not a W2 cross-browser pass.

Approved-source preservation checks found 57 retained PNGs and matching approved hero/logo SHA-256 values, no rejected portal batch and only the existing minimal SVG in runtime assets. A scan of 97 source/client files found none of the configured secret values; owner credentials were absent from the runtime environment file. This does not establish Git tracking/staging status or a complete secret/security audit.

Final documentation review checked 38 Markdown files and 340 local file/heading links, with no missing targets and balanced code fences. Source review found no remaining account-notice callers, unsafe HTML/eval, browser credential storage or visitor-derived external request destination in the implemented boundary. Required later workflow and release checks remain unchecked.
