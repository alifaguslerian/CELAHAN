# Local stability and admin login

November 14, 2026

- The saved administrator password reached the second-factor challenge. Verification returned 429. The isolated account had ten failed verifications and an active account-level lock. After the lock expired, the saved password and a current authenticator code returned 200 and opened the admin management route with the admin capability on both the local production build and the development server on port 3100. The verification sessions were signed out afterward.
- The auth API now maps allowlisted second-factor failures to separate states for a rejected code, expired challenge, or account lock. The account form distinguishes a service failure and allows a fresh sign-in after an expired challenge. The Windows helper reads the existing encrypted credential file and copies one requested value. Its code and password branches were exercised with a clipboard stub that checked the shape without exposing the values.
- An initial local Chromium run exposed a guest route blocked by a database connection timeout. Requests without a session cookie skip authentication pool initialization. Requests with a cookie still use Better Auth to validate the session. Protected pages present a retry path when a service failure prevents loading private data.
- The PostgreSQL pool uses an eight-second connection or acquisition timeout, a seven-second client query timeout, and a thirty-second idle lifetime. It handles idle disconnect events. Explicit transactions set five-second statement and three-second lock limits, verified with the restricted role on the pooled Neon test endpoint. The browser bounds form requests, keeps the existing mutation retry key, and checks idle ticket threads less often. See the [node-postgres pool API](https://node-postgres.com/apis/pool).
- Seven isolated migration hashes matched. An eight-query Neon sample ranged from 60 to 990 ms. A three-request sample per route on the final local production build measured 3–11 ms on subsequent requests to home, login and packages, and 16–23 ms on the guest package-to-login redirect including the destination. The first home response took 82 ms. These are local HTTP measurements, separate from browser rendering and production load.
- Production build, typecheck, lint and 20 unit tests passed. The locked npm graph returned zero reported advisories. Chromium passed ten public routes and twelve account routes in both languages, with keyboard and JavaScript-disabled public checks, zero outside requests and zero page errors. The private integration and Chromium journeys passed ticket intake, versioned scope approval, project creation, private publication, ownership denial, scheduling and retest follow-up.

The verification used the existing isolated test database and a local production build. It sampled connection variability and verified the application behavior for an account lock. It did not exercise sustained load or measure production availability.
