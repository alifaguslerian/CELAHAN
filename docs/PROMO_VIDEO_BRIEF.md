# CELAHAN — Promotional Video Brief

Status: Draft production direction; no visual storyboard, video assets, or render exists · October 27, 2026  
References: [Project Brief](PROJECT_BRIEF.md), [Design Direction](DESIGN_DIRECTION.md), [Implementation Plan](IMPLEMENTATION_PLAN.md)

## 1. Purpose

Introduce the CELAHAN concept, briefly demonstrate the service journey, and showcase the website's design and interactions. The video supports coursework and the frontend/product design portfolio.

The owner states that the lecturer requires a promotional video, but no duration, aspect ratio, format, or fixed deadline has been provided. Do not present proposed production specifications as confirmed lecturer requirements.

## 2. Audience and message

The primary audiences are lecturers and portfolio reviewers; general viewers should also understand the context without reading project documentation.

Core message: CELAHAN demonstrates a structured, permission-based web security assessment service with readable reports. Every website interaction is simulated. The video must not claim that the product has discovered vulnerabilities on real websites.

## 3. Visual direction

Cinematic motion graphics using the dark/amber identity, strong typography, carefully framed interfaces, and a pace that supports reading. Use motion to show the flow, status transitions, and relationships within report details. Avoid random-code montages or terminal effects resembling real attack operations.

The logo builds recognition; the mascot guides selected moments. Desktop and mobile UI demonstrations must still receive adequate attention. Show implemented features; clearly label concept footage that is not functional yet as a prototype.

## 5. Language and accessibility

The website requires ID/EN support; the primary video narration language is still open. The suggested approach is one master with Indonesian and English captions/subtitles, rather than committing to two full videos before the need is clear.

Primary text must not be too small or disappear too quickly. Provide captions and a transcript if narration is used. The core message must remain understandable without audio. Avoid rapid flashes. Music must not overpower narration; record sources and usage rights for music, sound effects, footage, and fonts.

## 6. Production inputs

- Final logo and mascot assets with editable sources.
- Recorded or rendered UI from a reviewed version, covering ID/EN and mobile/desktop.
- The same illustrative dataset and copy used on the website.
- Opening/closing copy, shot list, storyboard, and animatic.
- Licensed audio if used, captions, and a transcript.

Do not include real visitor identities, third-party target URLs, credentials, personal browser profiles, or hosting-account screenshots in footage. Clear desktop notifications and personal information before recording.

## 7. Production stages and completion criteria

1. Agree on format, duration, aspect ratio, language, audio, and publication channel.
2. Review the script and text storyboard for narrative accuracy and claim boundaries.
3. Create an animatic to assess pacing and readability before the final render.
4. Produce footage/motion from stable identity assets and website UI.
5. Review captions, audio, concept labels, UI accuracy, and licenses.
6. Export the master and publication versions in the agreed formats.

The video is complete when its message is understandable, it does not imply a real service/scan, text is readable, audio/captions are correct, and asset usage rights are recorded. Exporting a file is not the same as reviewing it.

## 8. Storage and website integration

Keep video sources and large renders separate from the website bundle. The owner chooses storage/release assets for GitHub tracking; agents do not upload them or run Git. The repository may record the brief, asset manifest, and final links once they exist.

V1 does not autoplay a hero video or embed a third-party player. If the completed video is linked later, use an explicit user action; player/integration choices are a separate change affecting performance and privacy.
